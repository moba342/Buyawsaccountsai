# Product status and purchasing audit

Date: 2026-11-27 (Asia/Dhaka). All 14 categories and 68 variations inspected. **0 commercial review records, 0 published variations, 0 purchasable variations.** All 82 catalog records remain technically indexable. No offer is activated by this audit.

## Root cause

The production publicationReviews object in [offer-review-records.js](../../offer-review-records.js) is empty. Every variant therefore fails productPublication, and every category lacks approved child offers and its category editorial review. These are deliberate commercial gates, not an SEO failure or a failed database query. There is no product database, inventory feed or admin-status API configured in this repository: records are static JavaScript. The seller profile/declaration and assigned buying keywords are not product authorization records.

## Pending-status messages

- **Pending verification / Pending review:** no completed commercial review for that variation; different UI labels represented the same unpublished state.
- **Not available to order:** purchasable=false; cart, checkout and backend enforce it independently.
- **Reference price:** seller-supplied catalog amount is retained for comparison; no confirmed review establishes an actual purchase price yet.
- **Category pending publication:** no reviewed child offer and/or category review. View Accounts and Details remain available to inspect catalog information.

The evaluator checks structured records and references; it does not itself verify authenticity, contact providers or poll live stock. A structurally passing record is not independently authenticated by this audit. No actual records have been invented or filled using test fixtures.

## UI defects corrected

1. Cards, provider cards and product buying-guide facts could label approved prices as reference prices; labels and provider price selection now distinguish reviewed and pending facts.
2. Approved-but-unavailable offers were inconsistently called pending in action ARIA labels, comparison actions, purchase summaries and backend errors. Availability labels now distinguish out-of-stock, pre-order/back-order-disabled and unreviewed states, without enabling them.
3. Product panels now show the actual reviewed availability, not just generic reviewed-offer wording.
4. Approved-cart subtotal/total and request text no longer imply their verified prices are unconfirmed; pending saved-cart labels remain reference-based.
5. The currently unused PurchaseSummary no longer tests only packages[0] when a later eligible option exists, and identifies the selected eligible product and price.
6. Home availability wording now checks purchasable offers rather than merely published (possibly out-of-stock) records.
7. Checkout holds distinguish missing publication from already-reviewed but unavailable stock; review approval and buyable availability remain jointly required.

No commercial eligibility requirements were weakened. Current real records remain held; approved-state behavior is exercised only with clearly synthetic, in-memory fixtures.
