# Independent SEO deployment checklist

SEO development has no mandatory commercial-document step. Commercial authorization/activation remains a separate workflow.

1. Review catalog-aligned metadata and keyword maps for all 82 records. No catalog prices/specifications or existing routes should change.
2. Run `npm test`, `npm run build`, `npm run validate:seo`. Expect 96 unique complete documents, 94 sitemap URLs, 69 social images, real 404s and cart/checkout noindex.
3. Run optional browser QA with `QA_TOOLS_PACKAGE_JSON` and `QA_EVIDENCE_DIR`; check eight widths, links, metadata/hydration, accessible controls and retained purchase/API safeguards.
4. Review actual performance measurements; no 120-FPS, field-INP, Google-indexing or rich-result guarantee.
5. Deploy only when a deployment is requested/approved. This task changes source and documents; it does not replace the live release or push changes to production main.
6. After release verify public canonical/robots/schema HTML, 94 sitemap URLs, established redirects, 404, purchase holds and server rejection. Rollback remains a separate deliberate release action.
7. Configure genuine Search Console verification and submit sitemap using owner access. Check actual URL coverage. Optional genuine analytics/privacy setup and rich-result follow-up are operational tasks, not SEO development blockers.

Do not invent commercial records, stock, certificates, services, return policies or support promises to increase an SEO score. Google merchant/product snippets may remain ineligible without genuine offers/reviews; factual catalog schema remains useful.
