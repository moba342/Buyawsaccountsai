# Structured data report

Initial HTML and SPA navigation use the same `seo.js` graph. Product pages describe actual supplied names, category, image, listed specifications and reference price. Collections/marketplace have ItemList links to the actual catalog, including commercially inactive entries. Organization, WebSite, WebPage, CollectionPage, BreadcrumbList and genuine guide Article remain.

Product identity is independent of a purchasable Offer. `confirmedOffer()` still enforces the separate existing commercial controls. No Offer, inventory/availability, rating, review, SKU, authorization or verification claim is invented for inactive products. Actual service scope is never inferred from archived service-keyword proposals.

Schema.org vocabulary validity and Google rich-result eligibility differ. Product information without an Offer, review or aggregateRating is **not currently eligible for Google's product snippets**; do not fabricate those properties to pass a merchant test. See [Google Product snippets requirements](https://developers.google.com/search/docs/appearance/structured-data/product-snippet). No rich result is promised. New-build external attempts are recorded in `evidence/independent-seo/external-validators.json`: Schema.org’s anonymous Code snippet editor timed out for homepage and product samples; Google accepted the code but returned “Something went wrong. Log in and try again.” No new external validation pass is claimed. Prior passes/errors are historical.

Local tests and generated-artifact validation cover product facts, canonical graph IDs, visible/schema breadcrumbs, safe JSON serialization, no false offers and explicit actual-service fixtures. Google Search Console and rich-result tool owner access remain separate operational actions, not prerequisites for implementation.
